# Architecture

(Sections 2–9, 11 and 15 of the original spec.)

## 2. Architecture overview

```
┌──────────────── MacHost (macOS menu-bar app, Swift) ────────────────┐         ┌──────────── PhoneClient (iOS, Swift + Metal) ─────────────┐
│ DesktopScanner → VirtualDisplayManager → WindowMover, DisplayArranger│         │ HostConnection (Bonjour browse, WebSocket, TCP)           │
│ DisplayCapture (ScreenCaptureKit, 1 per panel)                       │  video  │  ├─ VideoDecoder (VideoToolbox, 1 per panel)              │
│   → VideoEncoder (VideoToolbox HEVC low-latency, H.264 fallback)     │ ──────► │  └─ SceneStore, InteractionController                     │
│   → HostServer (Bonjour, WebSocket control, TCP video)               │ ◄────── │ ARSessionController (60 fps format, ARWorldMap)          │
│ SceneStore (single source of truth, JSON persistence)                │ control │ Renderer (camera bg, panels, handles, cursor, HUD)        │
│ InputModeController (CGEventTap, Esc, cursor lock/warp)              │         │   → 2 eye textures → DistortionPass → screen              │
│ CursorStreamer, QualityController, ControlPanel (SwiftUI)            │         │ PanelPixelMeter → QualityGovernor → quality_request      │
└──────────────────────────────────────────────────────────────────────┘         └───────────────────────────────────────────────────────────┘
            Shared Swift package: protocol messages, video framing, Annex-B, layout math, hit testing,
            input-mode state machine, layout keymap, AR cursor math, quality ladder/governor, clock sync
```

Ownership rules:
- The **Mac** owns the scene (panel list, sizes, levels, settings) and persists it.
- The **iPhone** owns ARKit world space: it computes panel transforms and reports them with `panel_update`; the Mac stores and rebroadcasts `scene`.

## 4. Mac side (MacHost)

### 4.1 Panel ↔ desktop mapping

| Panel | Source | API | Notes |
| --- | --- | --- | --- |
| Panel 1 (mirror) | Built-in display | ScreenCaptureKit on `CGMainDisplayID()` | Cannot be removed (only hidden) or rotated. 16:10; stream 1920×1200 or native per ladder |
| Panel 2…N | Virtual displays | `CGVirtualDisplay` + ScreenCaptureKit | 1920×1080 pt; HiDPI (3840×2160 backing) when N ≤ 3, 1× otherwise |

macOS does not render Spaces that are not visible, so they cannot be captured at the same time. That is why desktops 2…N become real (virtual) displays.

### 4.2 Startup sequence

1. **Permissions:** Screen Recording, Accessibility, Input Monitoring. The control panel shows what is missing with buttons that open the right System Settings pane.
2. **Read desktops (`DesktopScanner`):** via SkyLight private functions resolved with `dlsym` (fail soft, never crash): `CGSMainConnectionID`, `CGSCopyManagedDisplaySpaces` (ordered Spaces of the built-in display; use user desktops only, skip full-screen spaces), `CGSCopySpacesForWindows` together with `CGWindowListCopyWindowInfo` (which window is on which desktop). Read-only; no SIP changes. If reading fails, the user picks N manually in the control panel.
3. **Create displays (`VirtualDisplayManager`):** N−1 virtual displays named "DesktopAR 2…N".
4. **Move windows (`WindowMover.distribute`):** for k = 2…N switch to desktop k by posting ⌃k (the "Switch to Desktop k" shortcuts must be enabled; check this and warn the user if they are off), wait until the active Space changes, move that desktop's windows with the Accessibility API (`AXPosition`, `AXSize`) onto virtual display k−1 keeping their relative frames, then return to desktop 1. Send progress as `startup_scan` so the headset shows "Masaüstü 3/5 taşınıyor". With 5 desktops this takes a few seconds and the screen visibly switches — acceptable.
5. **Arrange (`DisplayArranger`):** `CGBeginDisplayConfiguration` / `CGConfigureDisplayOrigin` / `CGCompleteDisplayConfiguration(.forSession)` so the macOS display order matches the panel order left → right. Repeat whenever panels are reordered in AR (moving the mouse right enters the panel that is physically to the right).
6. **Start streaming:** one `DisplayCapture` + `VideoEncoder` per panel; `HostServer` starts listening and advertising.
7. **Quit (`WindowMover.restore`):** for each virtual display switch to its desktop and move its windows back onto the built-in display (they land on that desktop), then destroy the virtual displays. Also destroy virtual displays from `atexit` and signal handlers so a crash never leaves ghost monitors.
- "Rescan" button and the menu item re-run steps 2–5 if the desktop count changes during a session.

### 4.3 Modules

1. **DisplayCapture** — one `SCStream` per panel. `minimumFrameInterval` 1/60, `showsCursor = false` (the phone draws the cursor), `queueDepth` 3, pixel format 420v (or BGRA if needed), IOSurface-backed `CVPixelBuffer`, no copies. Exclude DesktopAR's own windows from capture. Output size is driven by the quality level (`SCStream.updateConfiguration`).
2. **VideoEncoder** — one `VTCompressionSession` per panel. Encoder specification `EnableLowLatencyRateControl = true`, properties `RealTime = true`, `AllowFrameReordering = false`, long keyframe interval, forced IDR on request. Try HEVC first; if the low-latency session fails (known error −12902 on some setups) fall back to H.264 automatically. Output Annex-B; every keyframe carries its parameter sets inline (VPS/SPS/PPS or SPS/PPS from the format description).
3. **VirtualDisplayManager** — create / destroy / change mode (resolution, HiDPI, landscape ↔ portrait) via `CGVirtualDisplayDescriptor`, `CGVirtualDisplay`, `CGVirtualDisplaySettings`, `CGVirtualDisplayMode` (Objective-C interfaces declared in `PrivateAPI/CGVirtualDisplay.h`, exposed through the bridging header). Reference implementations: DeskPad (github.com/Stengo/DeskPad) and VirtualDisplayKit.
4. **DesktopScanner / WindowMover / DisplayArranger** — section 4.2.
5. **InputModeController** — section 6.
6. **CursorStreamer** — screen mode only: ≤ 120 Hz, send `cursor` (panel + u/v) only when it changes; send `cursor_image` (PNG of `NSCursor.currentSystem`, hotspot, size) when the image hash changes. If the image is unavailable, the phone draws a default arrow.
7. **QualityController** — section 9 (Mac half).
8. **HostServer** — Network.framework: `NWListener` with `NWProtocolWebSocket` on the control port (Bonjour advertised here, TXT `v=1`, `video=<port>`) and a plain TCP `NWListener` for video. One phone at a time; a new connection replaces the old one. Back-pressure rule from section 10.
9. **SceneStore** — panels, calibration, settings, revision counter; persisted as JSON in Application Support; broadcasts `scene` after every change.
10. **ControlPanel (SwiftUI)** — menu-bar extra + window: connection status, permission checklist, desktop count (detected / manual override, Rescan), panel list (visible, level, orientation), exit key style, calibration sliders (live), stats, top-down layout preview.

Logging everywhere: `os.Logger(subsystem: "dev.desktopar.host", category: …)`. No `print`.

## 5. iPhone side (PhoneClient)

Single Swift app, rendering with Metal (`MTKView`). Camera frames (ARKit) and decoded video frames are IOSurface-backed `CVPixelBuffer`s turned into Metal textures with `CVMetalTextureCache` — no copies, everything stays on the GPU. No game engine and no RealityKit (RealityKit controls its own camera and cannot render the two-eye split).

### 5.1 Components

| Component | Technology | Job |
| --- | --- | --- |
| App shell | SwiftUI + `MTKView` | Landscape-right lock, `isIdleTimerDisabled`, full screen, max brightness |
| HostConnection | Network.framework (`NWBrowser`, WebSocket, TCP) | Discover the Mac, connect both channels, `hello`, `ping` every 2 s, auto-reconnect (keep showing the last frames + HUD "yeniden bağlanıyor") |
| VideoDecoder | `VTDecompressionSession`, one per panel | Annex-B → length-prefixed `CMSampleBuffer`, format description rebuilt from inline parameter sets, real-time decode, output BGRA Metal-compatible; keeps only the latest frame (lock-protected slot) |
| ARSessionController | ARKit `ARWorldTrackingConfiguration` | 6DoF head pose, camera image, plane detection, **60 fps video format** chosen from `supportedVideoFormats`, `ARWorldMap` save/load |
| Renderer | Metal | Camera background, panels, handles, cursor, HUD into two eye textures |
| DistortionPass | Metal fragment shader | Barrel distortion, chromatic correction, circular mask, sharpen → screen halves |
| InteractionController | Shared math | Layout-mode AR cursor, hit testing, drag/resize state machine, layout commands |
| PanelPixelMeter | Shared math | Sharpness module (iPhone half) |
| HUD | CoreText → texture | Short notices ("Masaüstü 2/2", "Ana ekran döndürülemez", mode changes) |

### 5.2 Frame loop (60 Hz, `preferredFramesPerSecond = 60`; ProMotion 120 Hz not used in v1 to save heat)

1. Latest `ARFrame` → head pose + camera Y/CbCr textures.
2. For each panel, the decoder's latest texture (or the previous one). Never wait.
3. For each eye: view = head pose · translate(±IPD/2); projection from the calibrated FOV. Draw: camera background, panels (flat or curved grid mesh), layout-mode highlight and handles, cursor (screen-mode sprite at the panel's u/v, or the layout-mode ring), HUD.
4. Distortion pass writes both eye textures to the left and right halves of the drawable.

Eye textures are rendered at `supersample` × the per-eye size (default 1.25), reduced automatically under thermal pressure.

### 5.3 Passthrough

- One camera → no true stereo. The same camera image goes to both eyes as a distant plane; panels are rendered in real stereo and sit at their depth (standard Cardboard passthrough approach).
- Scale the camera image from `ARCamera.intrinsics` so the real keyboard and trackpad appear at their real size; the user sees them through the camera. The camera FOV is narrower than the lens FOV → dark borders are normal.
- Background and panels use the same ARKit pose, so panels never swim relative to the room.
- **VR mode** (toggle): camera off, dark background — less heat, for long sessions.

### 5.4 Lens calibration (no button, no QR)

- Parameters: lens separation (mm), screen-to-lens distance, vertical offset, k1, k2, FOV, chromatic aberration, sharpen strength, supersample. Initial defaults: 63 mm, 39 mm, 0, 0.34, 0.55, 90°, 0.008, 0.3, 1.25 — real values come from measuring with a ruler and the test pattern.
- Adjusted live from the Mac control panel, or in layout mode with **K** (calibration mode: arrow keys select field / change value). Changes apply immediately.
- Test pattern: a grid + centre cross per eye. Tune until grid lines look straight and the two crosses fuse into one. Store the profile on the phone and on the Mac.
- Distortion model: r' = r·(1 + k1·r² + k2·r⁴), per-channel radial scale for chromatic correction, circular mask matching the lens.

### 5.5 Persistence

- Each panel is attached to an `ARAnchor`. Save `ARWorldMap` (debounced after changes and when the app goes to background).
- On launch load the map; after looking around for a few seconds ARKit relocalises and panels appear where they were left.
- If relocalisation does not happen within ~10 s, place the layout relative to the current view and offer "re-anchor" (HUD + key 0).
- LiDAR plane detection lets panel edges snap to walls and the desk.

### 5.6 Thermal and power

Watch `ProcessInfo.thermalState`. Steps as it rises: lower supersample → non-focused panels 30 fps → ARKit 30 fps format → suggest VR mode. A charging cable is fine for long sessions; data still goes over Wi-Fi.

Development note: with a free Apple ID the app must be re-installed from Xcode every 7 days.

## 6. Input modes (keyboard + trackpad only)

### 6.1 Mode switching

| Situation | Result |
| --- | --- |
| Layout mode, click inside a panel | Screen mode; macOS cursor warped to the clicked point of that display |
| Screen mode, exit key (default Esc) | Layout mode; macOS cursor hidden + frozen; AR cursor starts where the macOS cursor was |
| Layout mode, Enter | Screen mode at the centre of the panel under the AR cursor |
| App launch | Screen mode |

### 6.2 How it works on the Mac (`InputModeController` + pure `InputModeMachine` in Shared)

- A `CGEventTap` (session level, head insert) is always installed.
- **Screen mode:** the tap only inspects key-down events; when the machine says "exit key", the event is swallowed and the mode switches. ⌘Esc / ⌥Esc (e.g. Force Quit) are never intercepted. Key repeats never switch.
- **Entering layout mode:** hide the cursor (`CGDisplayHideCursor`; background apps may need the `SetsCursorInBackground` connection property — best effort, it is not critical because the cursor is not in the video), freeze it with `CGAssociateMouseAndMouseCursorPosition(false)`, then swallow all mouse, scroll, magnify and keyboard events. Mouse deltas (`mouseEventDeltaX/Y`), button down/up, scroll and trackpad magnification go to the phone as `ar_input`; key presses are mapped by `LayoutKeymap` and sent as `layout_command`.
- **Back to screen mode** on `enter_screen` (panel + u/v): convert to the display's global coordinates, `CGWarpMouseCursorPosition`, re-associate the mouse, show the cursor, stop swallowing.
- Double-Esc style: the first Esc passes through and starts a 350 ms window; a second Esc inside it switches. ⌃Esc style: only ⌃Esc switches.

### 6.3 AR cursor (phone)

- A direction (yaw/pitch, world space) from the head, moved by mouse deltas (≈ 0.0022 rad per point; moving the mouse right turns right, down turns down).
- Clamped to the visible field of view so it can never be lost.
- Drawn as a ring + small arrow: on a panel it sticks to the panel surface; otherwise it floats 2 m away.
- When layout mode starts, it is aimed at the world point where the macOS cursor was on its panel.

### 6.4 Hit testing and handles

When the AR cursor is over a panel, the panel is highlighted and its handles appear. Regions in panel-local metres (panel centred at origin, face +Z):

| Region | Geometry |
| --- | --- |
| Content | Inside the panel → u, v in 0…1, origin top-left (macOS coordinates) |
| Move bar | Below the panel: gap 0.02 m, height 0.035 m (+0.01 m slack), width 35 % of the panel (0.15–0.6 m) |
| Resize corner | 0.08 m square centred on the bottom-right corner (wins over content) |
| Rotate · Add · Close buttons | Above the panel: 0.06 m squares, 0.02 m gap, spaced 1.3 × size, left → right |

Curved panels are hit-tested as their flat chord. The nearest hit along the ray wins. Handle regions count as hovering their panel, so the handles stay visible while you reach them.

### 6.5 Mouse actions in layout mode

| Action | Where | Result |
| --- | --- | --- |
| Click | Panel content | Screen mode at that point |
| Drag | Move bar (or ⌥ + drag anywhere on the panel) | Panel orbits around the head (left/right, up/down), keeps facing the user |
| Drag | Resize corner | Resize, aspect kept |
| Trackpad pinch | Over a panel | Resize |
| Two-finger vertical scroll | Over a panel | Closer / farther along the head → panel ray |
| Click | Rotate | Landscape ↔ portrait |
| Click | + | New virtual display to the right of this panel |
| Click, then click again to confirm | × | Remove virtual display; hide the mirror panel |

### 6.6 Keys in layout mode (keyboard does not reach apps here)

Letters and symbols are matched by the produced character (layout-aware, works with the Turkish Q keyboard where Ğ/Ü sit at [ ]); arrows, delete and return by key code. Commands apply to the panel under the AR cursor.

| Key | Command |
| --- | --- |
| R | Toggle landscape / portrait |
| H / V | Make landscape / portrait |
| F | Turn the panel to face me |
| Arrows | Move (⇧ = big step) |
| + / − (also =, *, keypad) | Bigger / smaller |
| [ / ] (also , / . and Ğ / Ü) | Closer / farther |
| C | Curvature on / off |
| N | New virtual display |
| ⌫ | Remove / hide panel (confirm with a second press) |
| G | Show hidden panels |
| 0 | Bring everything in front of me |
| P | Passthrough ↔ VR mode |
| K | Calibration mode |
| Enter | Screen mode |

Every command shows a short HUD notice. In screen mode ⌃⌥P (passthrough) and ⌃⌥0 (bring everything in front) also work as global shortcuts.

### 6.7 Rotation

- Virtual displays: the Mac switches the virtual display mode 1920×1080 ↔ 1080×1920; macOS re-lays out the windows. In AR the old height becomes the new width (area preserved) once the Mac confirms the change via `scene`. 1–2 s is acceptable.
- Mirror panel: rotation disabled in v1 → Mac replies with `hud` "Ana ekran döndürülemez".
- The quality ladder uses portrait sizes (width/height swapped) for portrait panels.

### 6.8 Adding and removing

- **Add:** + / N → `add_display` → the Mac creates a virtual display → the panel appears to the right of the hovered panel (macOS needs 1–2 s to see the new display). Upper limit configurable (default 6).
- **Remove:** × twice / ⌫ twice → `remove_display` → macOS moves its windows to the built-in display, the panel disappears.
- **Limits:** width 0.3–4 m, distance 0.5–5 m, pitch ±1.2 rad.
- **On release:** new `ARAnchor`, sharpness module re-evaluates, macOS display order re-synced, `ARWorldMap` saved.

## 7. Geometry conventions (Shared `LayoutMath`)

- ARKit world space: right-handed, +Y up; the user looks along −Z at yaw 0; positive yaw turns left.
- Direction for yaw φ, pitch θ: (−sin φ·cos θ, sin θ, −cos φ·cos θ).
- Panel local frame: face along +Z (toward the user), +X right, +Y up, origin at the centre. Transforms are column-major `simd_float4x4`, serialised as 16 floats.
- **Default layout (`arcLayout`):** panels in desktop order left → right on an arc of radius 1.4 m around the head at eye height, 0.08 m gaps, centred on the current view direction, each facing the head.
- **Orbit (move):** convert the panel position to yaw/pitch/radius around the head, add the deltas (mouse right → yaw decreases), rebuild, face the head (with vertical tilt toward the head).
- **Distance:** move along the head → panel ray, clamp 0.5–5 m.
- **Rotate:** new width = old height (clamped), aspect = 1/aspect.

## 8. Rendering details

- **Background:** camera Y/CbCr → RGB in the fragment shader, mono for both eyes, scaled from intrinsics.
- **Panels:** grid mesh (e.g. 32×1 segments) bent into a cylinder section by `curvature`; sample the decoded texture (bilinear; mipmapped copy when the panel is small/far to stop text shimmering); MSAA 4× for clean edges.
- **Handles / highlight:** flat shaded quads in panel space (`PanelHandleGeometry` from Shared so rendering and hit testing never disagree).
- **Cursor:** screen mode → textured quad from `cursor_image` at the panel's u/v, slightly in front of the panel, size adjustable; layout mode → ring + arrow.
- **Distortion pass:** per eye viewport = half of the drawable; lens centre offset by lens separation and vertical offset; barrel distortion; per-channel radial scale; circular mask; optional CAS-style sharpen.

## 9. Sharpness module ("Netlik modülü")

Goal: a bigger or closer panel becomes sharper. 1–2 s transitions are acceptable.

**Loop**
1. **Measure (iPhone, `PanelPixelMeter`):** every frame project the panel corners onto the eye texture → covered pixels along the long edge ÷ visible fraction (< 1 when the panel exceeds the view) × 1.3 oversample → smallest ladder level that covers it.
2. **Stabilise (`QualityGovernor`):** the target must stay the same for ≥ 1 s; never while dragging/resizing; then send `quality_request`.
3. **Apply (Mac, `QualityController`):** `SCStream.updateConfiguration` output size + encoder size/bitrate, then a keyframe.
4. **Transition (iPhone):** keep showing the old texture scaled until the new size arrives. No black frame.

**Source:** virtual displays use a fixed logical size (1920×1080 pt) with HiDPI backing, so changing the ladder level never moves windows or changes text size — only the captured output size changes. The mirror panel's ceiling is the built-in display's native resolution. If the M1 cannot sustain HiDPI backing, use 1× and cap at L2.

| Level | Landscape size | Bitrate (approx.) | When |
| --- | --- | --- | --- |
| L1 | 1280×720 | 6 Mbps | Small/far panel, or not focused under load |
| L2 | 1920×1080 | 15 Mbps | Default |
| L3 | 2560×1440 | 25 Mbps | Panel fills most of the view |
| L4 | 3840×2160 | 40 Mbps | Panel larger than the view, single focused panel |

**Encoding-side sharpness**
- Idle refresh: if a display has not changed for 300 ms, re-encode the last frame at high quality (flag bit3) so text becomes crisp after scrolling. ScreenCaptureKit sends no frames for a static screen, so `QualityController` keeps the last pixel buffer.
- Text-first rate control: high bitrate ceiling and high minimum quality; desktop content changes little, so the average stays low.
- Chroma: 4:2:0 blurs coloured text. Try HEVC 4:4:4 on the M1 encoder / A15 decoder; if unsupported, the ladder compensates.

**Render-side sharpness:** supersampled eye textures, mipmaps for small panels, sharpen in the distortion pass, MSAA panel edges.

**Later (not v1): focus tile** — for panels larger than the view, stream a 1080p base layer plus a native-resolution crop (`SCStreamConfiguration.sourceRect`) of the region being looked at, composited on the phone.

## 11. Performance policy

**Latency budget (estimate, to be measured in F2)**

| Stage | Target (ms) | How |
| --- | --- | --- |
| Capture (60 Hz) | 0–16 | `minimumFrameInterval` 1/60, short queue |
| Encode (M1) | 3–8 | Low-latency mode, no B-frames |
| Wi-Fi | 2–15 | ≤ 2 queued frames |
| Decode (A15) | 3–8 | Real-time decode, frame straight to texture |
| Render + display | 10–25 | Always the newest texture |
| **Total** | **~30–75** | Ceiling 500 ms |

**Frame-rate policy:** the focused panel (`gaze_focus`) stays at 60 fps. Under load (encoder backlog, thermal state, many panels): other panels 30 fps → other panels L1 → with 5+ panels others 15 fps → focused panel 30 fps. The phone render loop is always 60 Hz, so head motion stays smooth even when video drops to 30.

**M1 8 GB:** 2–3 panels all 1080p60. 4+ panels: 1× backing for virtual displays, non-focused panels 30 fps (15 fps with 5+), ladder above L3 only for the focused panel. How many virtual displays the M1 handles is tested in F0.

**Bandwidth:** 1080p60 HEVC desktop content ≈ 10–20 Mbps per panel, video ≈ 25–35 Mbps. Fine for one room on 5 GHz Wi-Fi. The phone reports stats every second; the Mac adjusts bitrate.
